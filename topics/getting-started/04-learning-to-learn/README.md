自学技术最大的难点不是内容难，而是「看过就忘」和「卡住了不知道怎么办」。这一关给出一套可执行的方法：怎么学进去、怎么记得住、怎么自己找到答案、实在找不到时怎么问别人。

## 闯关任务

- [ ] 能够用自己的话做笔记，并按固定结构整理到仓库或笔记软件里。
- [ ] 能够用引号、`site:`、排除词等搜索技巧，在官方文档和社区里找到答案。
- [ ] 能够按「提问的智慧」写出一个包含环境、现象、最小复现和已尝试办法的好问题。

## 知识要点

### 费曼学习法：用「讲出来」检验「懂没懂」

这个方法以物理学家费曼命名（名字是后人起的，流程是对他学习方式的总结），核心只有四步：

1. 选一个概念，比如「DNS 是什么」。
2. 假装讲给一个完全不懂的人听，用最简单的话写下来或说出来。
3. 卡住、需要用术语糊弄的地方，就是你没懂的地方，回去重学。
4. 再讲一遍，直到能用比喻和例子讲顺。

### 主动回忆和间隔重复

- **主动回忆**：合上书自己回想，比再读一遍记得更牢。心理学里叫「测试效应」，所以本路线每关都有「通关自测」。
- **间隔重复**：遗忘先快后慢，在快忘的时候复习一次，下一次复习就可以隔得更久（1 天 → 3 天 → 1 周 → 1 个月……）。
- **工具**：Anki 等卡片软件会自动安排复习时间。Anki 的传统调度算法源自 SM-2，较新的版本还可以在牌组选项里改用 FSRS 调度器。一张卡片只问一个点，例如正面写「1 Byte = ? bit」，背面写「8」。

### 专注与休息

- 用番茄工作法之类的节奏：专注 25 分钟、休息 5 分钟，四轮后长休息。具体时长可以自己调。
- 学难的东西卡住时，暂时离开去散步、睡一觉，常常回来就想通了。《Learning How to Learn》课程把这叫作「专注模式」和「发散模式」交替。
- 「刻意练习」：专门练自己不会的部分，并且有反馈（自测、运行结果、别人的评审），而不是重复已经会的。

### 做笔记

- 用**自己的话**写，不复制粘贴大段原文；原文只放链接。
- 每篇笔记回答三个问题：这是什么？为什么需要它？怎么用（附一个最小示例）？
- 建议用 Markdown 写，学完 [Git](../../cs-basics/04-git/) 后放进 GitHub 仓库，本仓库的 [笔记模板](https://github.com/huangyongliang/tech-notes/tree/main/templates) 可以直接拿来用。
- 记下「疑问与待办」，学到后面再回来回答，这是最好的复习。

### 搜索技巧

| 写法 | 作用 | 例子 |
|------|------|------|
| `"..."` | 精确匹配整句 | `"segmentation fault" gcc` |
| `site:` | 只在某个网站里搜 | `site:docs.github.com pull request` |
| `-词` | 排除某个词 | `python list -snake` |
| 加版本号 | 避开过时答案 | `gcc 14 c23` |

- **报错信息原样复制**去搜，去掉自己的文件名、路径这些独有部分。
- **先官方文档，再社区**：官方文档最准确；Stack Overflow、GitHub Issues 看回答日期和票数。
- **用 AI 助手要核对**：它给的命令和链接先在官方文档里确认，代码要实际跑一遍。

### 提问的智慧

好问题让别人「一眼看懂、一次复现」。提问前先做三件事：搜索报错原文、查官方文档、试着缩小问题范围。提问时包含：

1. **目标**：你想做成什么（防止「XY 问题」：只问自己设想的解法 Y，却不说真正的目标 X）。
2. **环境**：操作系统、软件版本。
3. **最小复现**：能复现问题的最短代码或步骤。
4. **完整报错**：原样粘贴文字，不要截图后只剩半句。
5. **已尝试**：做过什么、结果如何。

```text
标题：Ubuntu 24.04 上 gcc 编译 hello.c 报 "undefined reference to `main'"

目标：编译并运行一个最简单的 C 程序。
环境：Ubuntu 24.04，gcc 13.2。
复现：hello.c 内容如下（附 5 行代码），执行 gcc hello.c -o hello。
报错：（完整粘贴终端输出）
已尝试：确认文件已保存；搜索报错后检查了 main 的拼写，仍然报错。
```

## 常见误区

- **把「看懂了」当成「学会了」**：看视频时觉得都懂，合上就写不出来。每学完一节都要动手和自测。
- **收藏等于学习**：收藏夹里的 100 个链接不如认真读完 1 个。本路线每关只推荐 3–6 个资源，就是为了少而精。
- **一遇到问题就问**：别人帮你搜一遍不如自己搜，而且自己找到的答案记得最牢。先花 15–30 分钟独立排查，再提问。
- **只截图不贴文字**：截图不能复制、不能搜索，报错和代码请贴文本。

## 实践任务

1. 选第 1 关的「二进制」，用费曼法写一段 200 字以内、外行能看懂的解释。
2. 安装 Anki 或类似工具，把前三关的 10 个关键概念做成卡片，坚持复习一周。
3. 用表格里的四种搜索写法各搜一次，记下哪种最有用。
4. 找一个自己最近遇到的问题，按「提问的智慧」写成一篇完整的提问（不一定要发出去）。
5. 建一个「学习日志」文件，每天写三行：今天学了什么、哪里没懂、明天做什么。

## 通关自测

先独立作答，再展开参考答案核对；简答题答出要点即算对。答对 ≥ 80% 即可进入下一关。

1. 【单选】下面哪种复习方式对长期记忆最有效？
    - A. 考前集中通读三遍
    - B. 合上书自测，并按逐渐拉长的间隔重复
    - C. 把重点全部抄一遍
    - D. 收藏好资料，需要时再看
2. 【单选】只想在 GitHub 官方文档里搜索 "fork"，应该输入：
    - A. `fork github`
    - B. `"fork" -github`
    - C. `site:docs.github.com fork`
    - D. `fork filetype:github`
3. 【单选】下面哪一项不是好的技术提问应包含的内容？
    - A. 软件版本和操作系统
    - B. 完整的报错文本
    - C. 「急！！！在线等」
    - D. 已经尝试过的办法
4. 【简答】什么是「XY 问题」？怎样避免？
5. 【简答】用费曼学习法检验自己是否懂了一个概念，关键的信号是什么？

<details markdown><summary>参考答案</summary>

1. B — 主动回忆加间隔重复，比集中重读记得更久。
2. C — `site:` 把搜索范围限定在某个网站。
3. C — 催促不提供任何有用信息，还会让回答者反感。
4. 只问自己设想的解法 Y，不说真正要解决的问题 X，导致别人帮错方向。避免方法：提问时先写清最终目标，再说你尝试的方案。
5. 讲给外行听时，如果必须用术语糊弄过去、或者讲不出例子，说明那里还没懂，需要回去重学。
