## 作用域是文本，生存期是时间 {#semantics-scope-lifetime}

绑定、作用域、生存期是三件事。绑定说的是一个名字这次指向哪个实体。作用域是这个名字在程序文本里可见的区域。生存期是对象在一次执行中存在的那段时间。

C 把作用域定义为程序文本中的区域：标识符只在它的作用域里可见。块作用域延伸到对应块的结尾。生存期则是执行中为对象保留存储的那段时间。进入被调用的函数会挂起当前块，但不会结束当前块。块被递归进入时，每次都会新建一个对象。

用同一个局部变量把两件事拆开：

```c
void f(int n) {
    int x = n;
    if (n > 0)
        f(n - 1);
}
```

`f(1)` 调用 `f(0)` 时，外层那次调用的 `x` 仍然活着，因为外层块还没结束。内层文本里的名字 `x` 指的是内层新建的那个对象，看不见外层那个。名字的可见范围没有变长，对象的存在时间也没有跟着内层文本一起结束。所以「这个名字在这里看不见」推不出「那个对象已经没了」。

Java 的作用域同样由声明在文本中的位置决定。一个局部变量的声明覆盖它可见的那段正文；这不是「这块内存还要留多久」。

## 词法作用域不看谁在调用 {#semantics-lexical}

静态作用域，也叫词法作用域，按文本上包围这段代码的声明来绑定名字。动态作用域按调用当时栈上最近的同名声明来绑定。

下面不是一段能在标准 C 里编译的嵌套函数，只用来对照两条规则。`g` 的正文不声明 `x`，`f` 和最外层各有一个 `x`。调用顺序是最外层调用 `f`，`f` 再调用 `g`，`g` 读取 `x`。

- 词法作用域：`g` 的正文被最外层的 `x` 包围，没有被 `f` 的正文包围。`g` 读到的是最外层那个 `x`。
- 动态作用域：查找沿着这次调用走。`g` 的调用者 `f` 有 `x`，于是读到 `f` 里那个 `x`。

两条规则把同一个名字绑到不同的对象。C 和 Java 采用词法作用域：看见哪个声明，由名字出现的文本位置决定，不由谁调用决定。动态作用域只作对照，不是这两份定义里的已定义行为。

## 参数传递复制的是值 {#semantics-parameters}

参数传递是语义规则，要写清复制的是什么。

C 的函数调用条款规定：准备调用时先求值实参，再把对应实参的值赋给参数。参数是函数里的对象，改参数就是改这个对象，不是改调用者的对象。下面的 `rebind` 返回后，调用者的 `n` 仍是调用前的值。`via_pointer` 写的是指针值所指的对象；被复制的是指针值，不是把调用者的变量改绑到别处。

```c
void rebind(int x) { x = 2; }
void via_pointer(int *p) { *p = 2; }
```

Java 也是把实参的值用来初始化一次调用里新建的参数变量。引用类型的值是引用，不是把对象再复制一份。被调方法给参数重新赋值，改的是参数变量，调用者的变量仍指向原来的对象。被调方法如果修改了那个对象的字段，调用者能看见，因为两边的引用值指向同一对象。这不是「被调方法把调用者的变量改绑了」。因此不能把 Java 概括成引用传递。引用传递通常指被调方能让调用者的变量改指另一个对象。Java 的方法做不到这件事，除非调用者传来的本来就是一个可以被改字段的容器。

这个条件只覆盖这里引用的 C 函数调用条款和 JLS 的参数初始化。不要写成所有语言都按值传递。

## 求值顺序是语义，未指定不是未定义 {#semantics-order}

表达式的值，和它在求值过程中产生的副作用，要分开写。定义可以规定副作用的顺序，也可以明确不规定。

Java 对多数二元运算规定从左到右：左操作数看起来完整求值之后，右操作数才开始。`&&`、`||` 和 `?:` 是写明的例外，未用到的那一侧可以不求值。方法调用的实参列表也是从左到右，每个实参完整求值后才轮到它右边的实参。

C 没有这条总的从左到右规定。标准自己把「函数实参的求值顺序」当作未指定行为的例子：文档给出多于一种可能，并且不要求每次选择同一种。未指定仍是有边界的。表达式条款另有一条：对同一个标量对象，若一个副作用相对另一个副作用或相对使用该值的运算是无序的，行为是未定义。未指定是「几种结果都合法」。未定义是「这份定义不再给保证」。结果因编译器而异，本身区分不了这两种。

## 十步以内的两种历史 {#semantics-derivation}

设 `a()` 打印 `A` 并返回 `1`，`b()` 打印 `B` 并返回 `2`。两者不修改同一个标量对象。表达式是 `a() + b()`。

Java 规定左操作数先完整求值：

1. 进入 `a()`。
2. 打印 `A`。
3. `a()` 得到值 `1`。
4. 进入 `b()`。
5. 打印 `B`。
6. `b()` 得到值 `2`。
7. 把 `1` 和 `2` 相加，表达式的值是 `3`。

可见历史只有一种：输出 `AB`，值是 `3`。

C 不规定这两个操作数谁先求值。在两者不冲突的前提下，下面两种历史都合法：

1. 先完成 `a()` 再完成 `b()`，输出 `AB`，值是 `3`。
2. 先完成 `b()` 再完成 `a()`，输出 `BA`，值是 `3`。

每种历史里每个函数只调用一次。值相同，副作用的顺序可以不同。这仍是未指定，不是未定义：标准允许这些选择，并没有说程序可以有任意行为。

若把例子改成在同一个表达式里对同一个标量无序地修改两次，表达式条款把它定为未定义。那时就不能再说「两种结果都合法，只是不知道是哪一种」。

## 常见误读 {#semantics-misreadings}

- 「作用域就是变量在内存里待多久。」作用域是名字在文本中可见的范围。生存期是对象存在的时间。递归调用里，外层对象还活着，内层文本已经看不见它。
- 「Java 传递对象就是引用传递。」传递的是引用的值。被调方法不能把调用者的变量改绑到另一个对象。能改的是对象里的状态，那是因为两边持有指向它的引用值。
- 「结果因编译器而异，所以这是未定义行为。」先看标准是给出了几种合法选择（未指定），还是对这种程序不再给任何保证（未定义）。实参求值顺序是前一种；对同一标量的无序副作用是后一种。

## 可选核对 {#semantics-check}

定义已经写在上面。这两问只核对两个容易并在一起的概念。

1. `f(1)` 正在执行内层的 `f(0)`。外层那次调用的 `x` 已经结束生存期了吗？内层的名字 `x` 指的是哪一个对象？
2. Java 方法把一个引用类型的参数赋成另一个对象。调用者的变量会改绑吗？

<details markdown><summary>参考答案</summary>

1. 外层对象的生存期还没结束，因为外层块被调用挂起，没有结束。内层的名字 `x` 指内层新建的对象。看不见外层的名字，不等于外层对象已经消失。
2. 不会。参数变量被赋了新的引用值，调用者的变量仍是调用前那个引用值。这不是引用传递。

</details>
