# 语法 {#syntax}

> [编程](../) › 语法

语法规定哪些符号串是合法程序，以及它们组成怎样的结构。它不决定表达式何时求值，也不决定类型是否合法。

## 先切成记号，再组成短语 {#syntax-tokens}

程序先被切成记号，再组成声明和表达式。C 的翻译阶段把源文件分解成预处理记号和空白（含注释）；每条注释被换成一个空格，换行保留。空白用来分开记号。除非语言另有规定，例如字符串字面量里面的字符属于那个记号，空白和注释不进入后面的短语结构。

Java 同样先做词法结构，再做句法。本页用 C 和 Java 说明这种默认情况。有的语言把缩进写进语法，那是那份定义自己的规定，不是这里的结论。

## 写法可以不同，结构可以相同 {#syntax-abstract}

具体语法是源文件里的写法，包括括号、关键字和分隔符。抽象结构是这些记号组成的树：哪个运算符是父节点，哪些表达式是它的操作数。定义关心的是这棵结构，不只是字符是否逐个相同。

`a + b` 和 `(a + b)` 可以对应同一次加法。多出来的括号是具体语法。它们没有在这个例子里变成另一个运算符。教材用「具体语法 / 抽象语法」这对词讲这件事。C 和 Java 的文本写的是自己的文法，不要把教材里的树直接当成标准条款。

## 歧义是两棵结构，不是读着别扭 {#syntax-ambiguity}

歧义是指同一串记号对应不止一棵结构。优先级和结合性属于定义，用来规定哪一棵结构合法。它们不是排版习惯。

悬挂的 `else` 是一个短例子。下面这一串可以让人想到两棵树：`else` 属于外层的 `if`，或者属于内层的 `if`。

```c
if (a)
    if (b)
        f();
else
    g();
```

同一点的 Java 对照：

```java
if (a)
    if (b)
        f();
else
    g();
```

C 的 `if` 语句条款写明：`else` 与词法上最近的、语法上允许配对的 `if` 连在一起。因此这里只有一棵合法的结构，`else` 属于内层。缩进写成外层的样子，也改变不了这棵树。

Java 把同一件事写进文法。JLS 14.5 说明，`else` 属于它可能隶属的最内层 `if`。`else` 前面的子语句必须是不会悬着一个短 `if` 的语句。执行方式并不因为这条限制而改变；限制只用来消去第二种结构。

运算符的优先级也是结构规则。C 和 Java 的表达式文法把乘除放在比加减更靠近叶子的一层，所以 `a + b * c` 的父节点是加法，右操作数才是乘法。这不是「先乘后加比较好看」。换一种语言，如果它的文法把这两层写反了，结构就不同。不能从 C 或 Java 推出所有语言都如此。

## 合法的结构还没有含义 {#syntax-not-meaning}

`x + y` 能构成加法表达式，只说明这串记号有一棵加法结构。它还不决定两个操作数何时求值，加法会不会溢出，也不决定 `x` 和 `y` 的类型是否允许相加。求值顺序在[语义](../02-semantics/)，类型在[类型系统](../03-types/)，溢出算不算已定义在[求值与内存模型](../04-evaluation-memory/)。能通过语法这一关，只表示结构合法。

## 常见误读 {#syntax-misreadings}

- 「能编译通过，语法就规定了运行结果。」编译器接受这棵结构，只说明实现认为它落在语法和后续约束里。结果仍要看语义、类型和内存条款有没有给出保证。
- 「换一种缩进或换行，含义一定变。」在 C 和 Java 里，空白分开记号，不选择 `else` 属于哪一个 `if`。只有语言把空白写进语法时，缩进才是结构的一部分。
- 「优先级是风格问题，不是定义。」文法把哪一个运算符放在父节点，就是结构定义。风格指南不能改写这条规则。

## 可选核对 {#syntax-check}

上一节已经写完哪一棵树合法。这两问只核对边界。

1. 把悬挂 `else` 的例子重新缩进，使 `else` 在视觉上对齐外层 `if`。C 的合法结构变了吗？
2. `x + y` 是合法的加法表达式。这是否已经规定两个操作数谁先求值？

<details markdown><summary>参考答案</summary>

1. 没有变。C 规定 `else` 属于词法上最近的那个允许配对的 `if`。缩进不是这条规则的输入。
2. 没有。语法只给出加法这棵结构。操作数的求值顺序是语义条款，而且 C 与 Java 的规定并不相同。

</details>
