## 未用到的操作数可以不算，这要定义允许 {#memory-strict}

严格求值是：函数的实参或运算符的操作数，在运算开始前就被算出。C 的函数调用条款规定，准备调用时实参要被求值。Java 同样在进入方法体之前求值实参；多数运算符也是先求值操作数，再做运算。

这不是「实现刚好比较勤快」。惰性求值是另一种定义：未用到的实参或子表达式可以不算，而且没算仍是符合定义的。C 和 Java 以严格求值为主。它们里也有写明的例外，例如 Java 的 `&&`、`||` 和 `?:` 可以不求值未用到的那一侧。例外是条款允许的策略，不是编译器私自省略。不能从 C 和 Java 推出所有语言都严格求值。

## 语言看见的对象，不是操作系统的页 {#memory-objects}

语言里的值、对象和引用，与操作系统的页表不是同一层。页表把虚拟地址映射到物理页。[计算机组成](../../cs-basics/01-computer-organization/) 和 [操作系统](../../cs-basics/02-operating-systems/) 讲那一层。本页只讲语言允许程序员看见的三件事：两个表达式是否可能指称同一对象（别名），这个对象是否被共享，以及它的寿命何时结束。

实现常常把自动存储期的对象放在调用栈上，把分配得到的存储叫作堆。栈和堆在这里是寿命模型的实现说法。它们不是「操作系统的页」，也不能用页的机制代替语言对寿命的规定。

## 谁撤回「这仍是一个有效对象」 {#memory-lifetime}

手动寿命和自动回收是两份不同的约定。

C 有自动、静态、线程和分配这几种存储期。对象的生存期是执行中保证为它保留存储的那段时间。在生存期之外使用该对象，或在生存期结束之后再使用指向它的指针值，行为是未定义。对分配得到的存储，寿命从成功分配延续到释放。释放就是撤回「这块存储仍是一个有效对象」。本页不教 `malloc` 怎么写。谁分配、谁释放、释放之后还能不能读，见[编程入门 03](../../programming-basics/03-memory-and-data/)。

Java 用可达性决定对象的存储何时可以回收。没有引用再把它当作可达对象时，回收器可以重用那块存储。程序员不是用一次显式释放来撤回保证。这并不表示对象的字段在两个线程之间自动可见，下一节单独写。

## 三种「没有唯一结果」，只有一种是撤回保证 {#memory-ub}

已定义的行为是标准写明会发生什么。除此之外，C 的术语条款把另外三种分开，每种都有标准自己的例子：

| 分类 | 定义还留下什么 | 标准举的例子 |
|------|----------------|--------------|
| 实现定义 | 有多种可能，实现必须记录自己选了哪一种 | 有符号整数右移时，高位如何填充 |
| 未指定 | 有多种可能，不要求实现记录，也不要求每次相同 | 函数实参的求值顺序 |
| 未定义 | 这份定义不再提出要求 | 解引用空指针 |

越界形成的指针若既不指向数组元素，也不指向末尾之后的那个位置，加法条款同样把它定为未定义。已经释放之后再读，是生存期条款里的未定义：对象的寿命已经结束。这两种都是撤回保证，不是「结果不稳定，但程序仍然合法」。标准允许的后果包括一直错下去，也包括在翻译或执行时终止。不能写成「一定会崩溃」。

Java 对这类空间安全问题通常换成明确的失败或干脆不让该操作进入语言。数组下标越界时，JLS 规定抛出 `ArrayIndexOutOfBoundsException`，而不是对整个程序不再提出要求。这不等于 Java 没有并发上的数据竞争。垃圾回收撤回的是「无人可达的存储仍被你占用」，不是「两个线程的写自动排好序」。

优化级别改变了结果时，先查程序是不是已经走到未定义行为。定义一旦不再提出要求，实现可以假定那条路径不会发生，并据此删除或改写其余代码。`-O2` 才看见的结果，可能是这个假定，而不必是编译器没有实现标准。先排除未定义行为，再谈实现缺陷。

未定义也不是「不可计算」。不可计算说的是不存在一个对所有输入都停机并答对的算法，那是[理论基础](../../cs-theory/)里的另一件事。未定义是这份语言定义对某些程序撤回了保证。

## 数据竞争和 happens-before {#memory-jmm}

并发的内存模型这里只到入门边界。JLS 17.4 用 happens-before 规定可见性：若动作 x happens-before 动作 y，则 x 对 y 可见，并且排在 y 之前。同一线程里的程序顺序、解锁与之后对同一管程的加锁、对 volatile 字段的写与之后的读、`start` 和 `join`，都会建立这种边。细节的锁和 `volatile` 写法不在本页，见 [Java 05](../../java/05-concurrency/) 和 [Java 06](../../java/06-jvm/)。

两个冲突的访问如果没有被 happens-before 排好，这次执行就有数据竞争。JLS 写明：没有数据竞争的程序，其执行看起来是顺序一致的。顺序一致是很强的全序：每个动作原子，并且立刻对所有线程可见。这个保证的前提是没有数据竞争。不能把顺序一致写成 Java 对含有数据竞争的程序的承诺，更不能写成多数语言的默认模型。

垃圾回收不建立 happens-before。对象仍然可达，只说明存储还没被收回，不说明另一个线程一定看得见最近一次写。

## 常见误读 {#memory-misreadings}

- 「未定义行为就是结果不确定，但还能当合法程序用。」未指定才是「几种结果都合法」。未定义是定义不再提出要求，程序不能再依靠一份规定好的结果。
- 「栈和堆是操作系统的页，和语言定义无关。」页是操作系统的映射机制。栈对象和堆对象是语言或实现用来谈论寿命的模型。
- 「Java 没有内存模型问题，因为有垃圾回收。」回收只处理可达性。没有 happens-before 的冲突访问仍然是数据竞争。
- 「加了 `-O2` 才出现的结果，一定是编译器 bug。」也可能是未定义行为让实现撤走了「这条路径仍有定义」的假定。先查程序，再断定实现违反标准。

## 可选核对 {#memory-check}

分类已经写在上一节。这两问只核对哪一种保证被撤回了。

1. C 程序在 `free` 之后又读那块存储。标准是否保证这次读取会崩溃？
2. 一段 Java 程序只使用垃圾回收，两个线程写同一个普通字段，中间没有 happens-before。还有没有数据竞争？

<details markdown><summary>参考答案</summary>

1. 不保证。生存期之外使用对象是未定义行为。标准不要求崩溃，也不再给一份确定结果。
2. 有。垃圾回收不建立 happens-before。两个冲突访问若没有这条边，按 JLS 的定义这就是数据竞争。

</details>
