# 类型系统 {#type-systems}

> [编程](../) › 类型系统

类型是语言对值和表达式的分类，并据此在编译期或运行期拒绝一些程序。通过检查不等于程序正确。

## 检查发生在翻译时，还是发生在运算时 {#types-when}

静态检查在翻译或装载这批程序时拒绝它。失败的保证是：程序不会以「已通过检查」的身份进入后面的执行。动态检查在某一次运算真正发生时拒绝它。失败的保证是一份已经写明的错误，例如抛出某个异常，而不是把整份语言定义撤回。

C 的类型约束能在翻译期诊断一部分不匹配，但检查比 Java 弱，而且强制转换可以绕过「这个值不该当那种对象用」。一个通过了翻译的 C 程序，仍可能在后面的条款里落入未定义行为。Java 在语言边界上更接近另一种约定：对不上的转换，要么翻译时就是错误，要么在运行时抛出写明的异常，而不是把「把整数当指针用」仍称作已定义。这是两份定义的对照，不是所有语言的共同底线。

[Python 速成](../../ai/00-python-bridge/) 只作动态检查的对照：值在运算发生时仍带有分类，失败是一次明确的错误。动态检查不是「没有类型」。本页不写 Python 教程。

## 健全是有条件的承诺 {#types-soundness}

类型健全的直觉说法是：在这套规则的前提都成立时，通过检查的程序不会以定义禁止的方式卡住。例如，不会把一个整数当作指针去用，还把这次使用称为已定义行为。

这个承诺依赖前提。规则没有覆盖到的转换、被程序员明确要求跳过的检查，都不在承诺里面。本页不把这句话写成定理，也不复述 progress 和 preservation 的证明。概念来自类型系统教材里的健全性直觉，资料索引会标明这一点。

## 比的是名字，还是形状 {#types-nominal}

名义类型比较的是声明的名字。结构类型比较的是字段和方法组成的形状，两个没有共同声明的类型，只要形状相符就可以被当成同一种。

Java 的类和接口是名义的。JLS 规定，两个引用类型在编译期是否为同一类型，要看它们是否来自同一声明：二元名相同，类型实参也相同。只是方法列表长得像，并不能使两个类变成同一个类型。本页只建立这个对照，不展开别的语言里的结构类型。

## 通过检查没有证明程序正确 {#types-not-correct}

类型规则拒绝的是它写明要拒绝的那些程序。它不因此保证下面任何一条，除非该语言另有条款：

- 程序会终止。
- 程序只使用有上限的内存或时间。
- 程序没有数据竞争。

Java 的类型检查不包含「这个循环一定会停」，也不包含「两个线程不会同时写同一个非 volatile 字段」。后一件事属于[求值与内存模型](../04-evaluation-memory/)和 [Java 05](../../java/05-concurrency/)。类型规则可以服务内存安全，例如拒绝把一个整数直接当成对象引用，但这不等于类型系统和内存安全是同一件事。

## 转换可以把检查推迟 {#types-casts}

强制转换、`void *` 和未检查转换是健全性的缺口。缺口成立的条件是：翻译期不再拒绝这次使用，改由程序员保证其后的访问仍然落在定义里面。

在 C 里，`void *` 可以携带一个对象指针，再被转换成另一种对象指针。转换本身可以是约束允许的。若随后按一个与对象有效类型不符的方式访问，就落到未定义行为那一侧。类型检查没有在转换这一步把程序挡下。

在 Java 里，未检查转换会保留编译，并把风险推迟。参数化类型的实参在擦除之后不再作为运行期的那种参数存在。之后若按一个更具体的类型去用，失败的形式是运行期的转换错误，而不是 C 那种「定义不再给任何保证」。擦除的写法见 [Java 03](../../java/03-core-advanced/)，本页只把它当作「运行期不再保留的参数」这一个例子。

因此「编译通过」只说明没有触发那些仍会在翻译期失败的检查。它不关闭上面这些被推迟的口子，也不证明程序没有运行错误。

## 常见误读 {#types-misreadings}

- 「动态类型就是没有类型。」检查发生在运算当时，值仍然被分类。失败时语言可以规定一个明确错误。没有提前拒绝，不是没有分类。
- 「通过编译等于没有运行错误。」翻译期没拒绝的程序，仍可能不停机、耗尽资源，或在被推迟的转换上失败。C 还可能在那之后进入未定义行为。
- 「类型系统和内存安全是同一件事。」类型规则可以拒绝一部分危险使用。对象的寿命、别名和数据竞争是第 04 章的承诺。通过类型检查没有自动获得那些承诺。

## 可选核对 {#types-check}

规则已经写在上面。这两问只核对健全性没有覆盖的边界。

1. 一个 Java 程序通过了类型检查。能不能据此断定它会终止？
2. C 里一次经 `void *` 的转换通过了编译。这次访问是否仍被定义为合法？

<details markdown><summary>参考答案</summary>

1. 不能。终止不是 Java 类型规则给出的保证。通过检查只说明程序没有被这套类型条款拒绝。
2. 不能。转换可以被约束允许，从而把检查推迟给程序员。按不符的类型访问对象，可以是未定义行为。编译通过没有把这个缺口补上。

</details>
