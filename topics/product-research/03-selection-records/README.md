# 选型记录 {#selection-records}

> [产品调研](../) › 选型记录

选型记录是一次带日期的取舍：问题、备选、判据、结果、依据，以及没选什么。它不是新的真理，也不是把技术章再抄一遍。

> [!NOTE]
> 本仓库和站点的内容由 AI 生成，资料与资源链接来源于网络，仅供学习参考；如有错误或侵权，请提 Issue 告知。

---

## 这一页补哪一块 {#selection-scope}

[问题与约束](../01-problem-constraints/) 给出要决定的问题和必须守住的条件。[对照与条件](../02-comparison/) 给出在那些条件下哪些做法可比、哪些不可比。本页只写取舍如何留下来。不写成架构决策记录的格式教程，不规定文件名、编号或仓库布局，也不重写任何技术栈。

## 记录里不能少的几项 {#selection-parts}

一份选型记录至少包含这些，少一项就核不全：

1. 要决定的问题，回链第 01 章，而不是另写一个愿望。
2. 纳入的备选。包括最后没选的。
3. 共同的判据，并且与第 01 章的约束对齐。
4. 取舍结果：选了哪一个。
5. 当时依据的事实：链到已有技术章或外部来源，不在本页复述。
6. 明确未选的东西，以及理由。

缺了「未选什么」，后来的人无法判断是没看见，还是看过并拒绝。只写「我们决定用 X」，把这六项收成了一句口号。

## 判据先于结果 {#selection-criteria}

判据必须先于结果写下。它回答的是：在已经写明的约束下，用什么来区分备选。先定结果再补判据，记录就失去核验价值。任何人都能为已经做出的选择找一组刚好成立的理由。先写下判据，结果才是这些判据的一次应用，而不是事后的说明。

判据对齐约束，而不是对齐宣传。第 01 章若写了「必须跑在已有的 JVM 服务里」，判据里就应有这一条，并且链到 [Java](../../java/) 里那条事实。本页只记录这条事实如何进入判据，不把 Java 章抄进来。「把技术章抄进调研才算有依据」会把事实和判断再次混成一篇。事实留在原处，记录只留指针和它在这次判据里的角色。

## 记录有时间 {#selection-dated}

选型是带日期的判断，不是新的真理。同一问题在约束变化后可以有另一份记录。上一份的问题、判据和结果不许悄悄改掉。怎样追加、怎样指向被取代者，是 [失效与修订](../04-invalidation/) 的事。本页先把「这份记录有时间」写清：日期属于记录本身，不属于后来补上的感想。

有一份决策模板，或某公司的决策文档，不等于这里的六项都在，更不等于判据先于结果。模板可以提醒栏目。栏目空着，或结果写在判据之前，记录仍然不能核。本页借用的是「处境、决定、后果，以及后来可以被取代」这一结构，不要求本仓库改成 ADR 文件。

## 一次取舍，不展开框架 {#selection-example}

约束来自第 01 章，并链到已有事实：已经有 Java 服务（[Java](../../java/)），需要浏览器里的客户端，并且不新开一门协议课（[Web](../../web/) 已有的边界就够用）。备选只有两个，单位相同。

- 备选甲：服务器生成第一份 HTML，浏览器展示这份文档。
- 备选乙：浏览器持有状态再推导界面，接口留在同一源。

判据先写下，并且只来自约束：不新增协议章；浏览器与接口的源关系必须能回到 [Web](../../web/) 已写的约定；实现落在已有的 JVM 服务上，而不是另起一个运行时。对照若发现某一条证据不可核，按第 02 章标成不可比，不打分。

结果可以是选甲或选乙。记录必须写下没选的那一个，以及它在哪一条判据上未满足或代价更高。例如没选乙，是因为当时的约束要求第一份文档由已有服务生成，而不是因为「单页比较新」。框架名字不进入这条记录。它们不是这次的判据。

## 常见误读 {#selection-misreadings}

- 「选型就是写一句『我们决定用 X』。」没有备选、判据、事实指针和未选项，这句话不能核。
- 「把技术章抄进调研，才算有依据。」依据是指针和它在判据里的角色。复述会把事实写成好像是这次调研新发现的。
- 「备选只写最后赢家即可。」没有未选项，后来的人分不清是拒绝过还是没看过。
- 「有了 ADR 模板或某公司的决策文档，就等于有了可核记录。」模板不代替判据先于结果，也不代替日期和事实指针。本仓库也不因此改成 ADR 布局。

## 可选核对 {#selection-check}

六项已经列在上面。这两问只核对记录能不能被后来的人核。

1. 记录写着「决定采用服务端生成的 HTML」，日期在结果之后才补上判据。它还有核验价值吗？
2. 备选只写了赢家，并附上整章 Java 笔记的抄录。未选项在哪里？依据算写清了吗？

<details markdown><summary>参考答案</summary>

1. 没有。判据若在结果之后补写，就不再是这次取舍事先遵守的条件。日期也说明不了判据当时就在。
2. 未选项缺失，所以分不清没看见还是拒绝了。整章抄录不是依据。依据应是指向 Java 或 Web 已有边界的指针，以及这条事实进入了哪一条判据。

</details>
