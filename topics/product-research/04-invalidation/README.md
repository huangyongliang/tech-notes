## 这一页补哪一块 {#invalidation-scope}

[选型记录](../03-selection-records/) 把一次取舍写成有时间的六项。本页只写这份记录如何失效、如何被取代，同时留下当时的判断。不写成项目管理流程，不教发布节奏，也不规定用 Git 的哪一种命令。痕迹可查时，用法见 [Git 版本控制](../../cs-basics/04-git/)，本页不重讲。

## 失效条件要先写出来 {#invalidation-conditions}

失效条件写在记录里，哪怕当时觉得不太可能。常见的是这四类：

1. 约束变了。第 01 章必须守住的条件不再是那一条。
2. 依据的事实变了。所依赖的版本边界更新了，或那一章撤回了某条保证。
3. 对照所用的证据过期，或被推翻。当时的出处不再描述现在的对象。
4. 问题本身被重写。要改变的事或「怎样算解决」换了，旧的对照单位就不成立。

这四类是连接何时断开的说明，不是追责。一份在其条件下正确的记录，可以在条件改变后被新记录取代。旧的问题、判据和结果留着，并写清它在哪一条上不再适用。当时记对了，和现在还是否适用，是两件事。

## 追加，而不是改掉 {#invalidation-append}

修订的合法方式是追加，或另开一份，并指向被取代者。直接改掉原结论、不留痕迹，第 03 章的「可核对」就落空：后来的人看见的只有新结论，看不见当时的判据。

被取代是一种状态，不是删除。新记录写明自己取代哪一份、击中了哪一条失效条件、新的对照或判据是什么。旧记录保持可读。这里只定这个原则，不规定文件名，也不规定用 Git 的哪一种操作。

新技术发布了，旧选型不因此自动作废。要看第 01 章的约束和第 03 章的判据是否真的被击中。没有被击中，就只是一条新的事实，还不是这份记录的失效。

## 引用的技术章变了，记录要重核 {#invalidation-facts}

选型记录里的事实是指针，不是抄来的正文。所指向的技术章若更新了版本基线，或撤回了某条保证，这份选型要被重新核验，而不是自动继续有效。

版本基线带日期，是本站技术章已经在用的写法，例如 [Java](../../java/) 主题页上的版本说明。日期变了，只说明事实可能变了，选型是否失效仍看判据有没有用到那一条。[DevOps](../../devops/) 里的来源证据也是带时间的陈述：标签可以改指向，摘要上的陈述才是当时承认的那一份。证据过期，不等于当时的选型记错，但继续沿用之前要再核一次。

## 约束击中「同一源」 {#invalidation-example}

当初的选型按这个约束做：浏览器里的页面和它调用的接口留在同一源，因此可以在「服务器生成第一份 HTML」和「浏览器持有状态、接口仍同源」之间取舍。判据指向 [Web](../../web/) 已写的边界，不依赖把 API 放到另一台主机。

后来的约束变成：接口必须拆到另一个主机。被击中的是「同一源」那一条，不是「用了哪一个框架」。旧记录在原来的约束下仍然成立，只是不再适用于新约束。新记录要做的是一次新的对照：跨源时脚本还能不能读到响应、凭证落在哪一侧。事实在 [跨越源边界](../../web/04-crossing-boundary/)。本页不重讲 CORS。新记录指向旧记录，写明取代原因是这条约束变了，并补上这次对照的日期和出处。把旧结论改成「当时就选了跨源」是抹掉，不是修订。

## 常见误读 {#invalidation-misreadings}

- 「决策一旦写下就永远有效。」记录在写下的条件下成立。约束、事实、证据或问题变了，适用性就要重核。
- 「条件变了，直接改原文就行。」改掉原结论而不留旧的问题和判据，后来的人无法再核当时为什么那样选。
- 「新技术发布了，旧选型就自动作废。」只有它击中了当时的约束或判据，这份记录才失效。否则它只是一条尚未进入判据的新事实。
- 「失效是在追责，不是在更新连接。」失效写的是哪一条连接断开了。它不把当时的判断改写成错误，除非当时的事实或推理本身不成立。

## 可选核对 {#invalidation-check}

取代和抹掉已经分开。这两问只核对旧记录还要不要留。

1. 所依赖的 Java 版本基线日期更新了，但当时的判据没有用到那一条版本差异。旧选型因此作废了吗？
2. 接口改到另一主机之后，有人把旧记录里的结论改成「选择跨源 BFF」，不保留原文。这是修订吗？

<details markdown><summary>参考答案</summary>

1. 没有。事实变了，但判据没被击中。应当记下这条新事实，并写明它尚未使这份记录失效。自动作废会把没被用到的变化当成断连。
2. 不是。这是抹掉。修订应另开一份，指向旧记录，写明「同一源」这条约束不再成立，并补上新的对照。旧的问题和结果仍要能读到。

</details>
