# 分布式系统模型 Distributed System Model

> [系统](../) › 分布式系统模型

这里的「分布式」指多台会独立失效的计算体只能靠消息协作。它不重写进程、TCP 或 SQL。

## 模型里有什么

一次运行由若干进程和它们之间的消息组成。这里的进程不是操作系统里的 `fork` 结果，而是一个会按自己的步调执行、并且可能停住的计算体。进程之间没有共享内存。谁要影响谁，只能送出一条消息，对方以后可能收到。

本页采用完全异步这个假设，沿用 Fischer、Lynch 与 Paterson 1985 年论文里的说法：不假设消息延迟有上界，也不假设各进程的相对速度有上界。局域网里延迟常常有经验上界。那是另一个模型。把异步模型里推不出的结论，说成「所以生产网络也永远做不到」，就换了假设。

部分失效是这个模型的基本现象：一个进程可以停住，其余进程继续执行。一台机器的内核如果整体停摆，那台机器上的进程会一起停。分布式模型讨论的是另一种情况：系统的一部分停了，另一部分还在对外服务。

## 超时不能区分两种历史

两个账户服务 A 和 B。客户端请 A 扣款，并请 B 入账。客户端把请求发给 A 之后，在自己选定的时限里没有收到响应。

至少有两种与客户端所见相容的历史：

1. 消息还在路上，或者 A 已经扣款但响应丢了。
2. A 在处理之前就停了，扣款没有发生。

客户端无法从「超时」这一件事推出是哪一种。再发一次请求，可能把一次扣款变成两次，除非请求本身带有服务端能认出的唯一编号。TCP 保证的是一条连接上的字节流，连接还在、并且双方都按协议收发的时候才谈得上可靠送达。[计算机网络](../../cs-basics/05-networking/) 里的 TCP 没有提供「对方进程已经崩溃」这个信号。异步模型里甚至不假设你能发现对方已死：论文写明，若能探测进程死亡，他们的不可能结论就不成立。

## 安全性质和活性

安全性质要求某类坏事永远不发生。对共识来说，论文里的部分正确包含：所有已经作出的决定都相同，并且决定值必须是某个进程提出过的值。活性要求某类好事终会发生。完全正确还要求每一次允许的运行里都有进程作出决定。

Fischer、Lynch 与 Paterson 的定理 1 是：在完全异步、至多一个进程会停住、并且发给未停进程的消息最终都会送达的模型里，没有一个共识协议是完全正确的。证明的要点是，任何号称总能决定的协议，都存在一条允许的运行，其中决定永远不出现。

这不是「共识没有安全性质」。同一篇论文的定理 2 给出一个部分正确的协议：若执行过程中没有进程死亡，并且开始时严格多数进程活着，则未停进程都会决定。办不到的是把「至多一个进程会停」和「每条允许的运行都终将决定」同时保证。随机化、部分同步或故障探测器改变的是假设，不是把这条定理的前提偷偷删掉。

[微服务](../../microservices/07-distributed-transactions/) 里的 Saga 和 Outbox 是业务层的做法：它们放弃「所有参与者同时提交或同时回滚」，改成可补偿或可靠地发出事件。那不是 FLP 定理的一种实现，也不说明 FLP 的前提在那些系统里成立。

## 常见误读

- 「用了 TCP，超时就等于对方没做」。超时只说明响应没有在本地时限内到达。
- 「操作系统时钟的时间戳能给所有事件排成全序」。时钟会偏差。本页不把墙上时钟当作逻辑顺序。
- 「异步模型证明了任何网络都不能达成一致」。定理依赖完全异步、确定性协议，以及必须在每条允许运行里终止。换掉其中一条，结论要重新证明。
- 「单库事务已经解决了部分失效」。单库事务的提交点在一个数据库里。[数据库基础](../../cs-basics/07-databases/) 不讨论两个独立进程各有各的提交点。
