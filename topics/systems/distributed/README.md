# 分布式系统模型 Distributed System Model

> [系统](../) › 分布式系统模型

这里的「分布式」指多台会独立失效的计算体只能靠消息协作。它不重写进程、TCP 或 SQL。

## 这一页补哪一块

[操作系统](../../cs-basics/02-operating-systems/) 讲一台机器上的进程、虚拟内存和锁。[计算机网络](../../cs-basics/05-networking/) 讲 IP、TCP 和 HTTP 的报文。[数据库基础](../../cs-basics/07-databases/) 讲单库里的 SQL 和事务。[微服务](../../microservices/07-distributed-transactions/) 讲 Saga、TCC 和 Outbox 怎么落地。那些章默认你已经知道：对方可能停了，而你还在跑，并且超时说明不了它到底做没做。本页只建立这个模型。

## 模型里有什么

一次运行由若干进程和它们之间的消息组成。这里的进程不是操作系统里的 `fork` 结果，而是一个会按自己的步调执行、并且可能停住的计算体。进程之间没有共享内存。谁要影响谁，只能送出一条消息，对方以后可能收到。

本页采用完全异步这个假设，沿用 Fischer、Lynch 与 Paterson 1985 年论文里的说法：不假设消息延迟有上界，也不假设各进程的相对速度有上界。局域网里延迟常常有经验上界。那是另一个模型。把异步模型里推不出的结论，说成「所以生产网络也永远做不到」，就换了假设。

部分失效是这个模型的基本现象：一个进程可以停住，其余进程继续执行。一台机器的内核如果整体停摆，那台机器上的进程会一起停。分布式模型讨论的是另一种情况：系统的一部分停了，另一部分还在对外服务。

## 超时不能区分两种历史

两个账户服务 A 和 B。客户端请 A 扣款，并请 B 入账。客户端把请求发给 A 之后，在自己选定的时限里没有收到响应。

至少有两种与客户端所见相容的历史：

1. 消息还在路上，或者 A 已经扣款但响应丢了。
2. A 在处理之前就停了，扣款没有发生。

客户端无法从「超时」这一件事推出是哪一种。再发一次请求，可能把一次扣款变成两次，除非请求本身带有服务端能认出的唯一编号。TCP 保证的是一条连接上的字节流，连接还在、并且双方都按协议收发的时候才谈得上可靠送达。[计算机网络](../../cs-basics/05-networking/) 里的 TCP 没有提供「对方进程已经崩溃」这个信号。异步模型里甚至不假设你能发现对方已死：论文写明，若能探测进程死亡，他们的不可能结论就不成立。

## 安全性质和活性

安全性质要求某类坏事永远不发生。活性要求某类好事终会发生。Fischer、Lynch 与 Paterson 的论文用两个专门术语来写这件事，不要把它们换成后来文献里常见的 validity。validity 通常要求：同一次运行的决定值必须等于该次运行中某个进程的输入。论文没有把这条写成部分正确的条件。

论文第 2 节里，每个进程有一位输入寄存器。配置包括各进程的内部状态和消息缓冲。初始配置中每个进程处于初始状态，缓冲为空。从某个初始配置经有限步能到达的配置，称为可及配置。某个进程的输出寄存器为 0 或 1 时，该配置具有这个决定值。

同一节（刊印页 377）规定，协议部分正确当且仅当：

1. 任何可及配置里的决定值不超过一个。已作出的决定彼此相同。
2. 对 `{0,1}` 中的每一个 v，存在某个可及配置，其决定值是 v。两种决定值都在可及配置的全体里出现过。

第 2 条是非平凡性，范围是可及配置的集合，不是同一次运行。它不要求该次运行的决定值来自该次运行的某个输入。一个永远只决定 0 的协议违反第 2 条。一个在全体输入都是 0 的运行里决定 1 的协议，论文的第 2 条并不因此禁止它。本页不把这种「决定值来自本次输入」称作论文已经证明的性质。

无故障指该进程在这次运行中走无穷步，否则称为故障。允许的运行至多有一个故障进程，并且发给无故障进程的消息最终都会被收到。有进程在该运行中进入决定状态，才叫这次运行作出了决定。尽管有一个故障仍完全正确，是指协议部分正确，并且每一次允许的运行都作出决定。

第 3 节定理 1（刊印页 377）说：没有共识协议是尽管有一个故障仍完全正确的。证明先假设存在这样的协议，再得到一条允许的运行，其中决定永远不出现。办不到的是：在这个完全异步模型里，同时保住上面的部分正确，又让每条允许的运行都终止于一个决定。

这不是「任何一致都不可能」，也不是「安全性质不可能」。刊印页 381 的定理 2 给出一个部分正确的协议：若执行过程中没有进程死亡，并且开始时严格多数进程活着，则未停进程都会决定。随机化、部分同步或故障探测器改的是模型假设。那些结果要另证，不能把定理 1 的原话搬过去。

[微服务](../../microservices/07-distributed-transactions/) 里的 Saga 和 Outbox 是业务层的做法：它们放弃「所有参与者同时提交或同时回滚」，改成可补偿或可靠地发出事件。那不是 FLP 定理的一种实现，也不说明 FLP 的前提在那些系统里成立。

## 常见误读

- 「用了 TCP，超时就等于对方没做」。超时只说明响应没有在本地时限内到达。
- 「操作系统时钟的时间戳能给所有事件排成全序」。时钟会偏差。本页不把墙上时钟当作逻辑顺序。
- 「异步模型证明了任何网络都不能达成一致」。定理依赖完全异步、确定性协议，以及必须在每条允许运行里终止。换掉其中一条，结论要重新证明。
- 「单库事务已经解决了部分失效」。单库事务的提交点在一个数据库里。[数据库基础](../../cs-basics/07-databases/) 不讨论两个独立进程各有各的提交点。
