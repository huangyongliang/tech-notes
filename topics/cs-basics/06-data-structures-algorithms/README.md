## 知识要点

### 复杂度与大 O

大 O 描述的是**输入规模 n 增长时，运行时间（或内存）的增长趋势**，忽略常数和低阶项：`3n² + 5n + 100` 记为 O(n²)。

| 复杂度 | 名称 | 典型例子 | n = 10⁶ 时的操作量级 |
|--------|------|----------|----------------------|
| O(1) | 常数 | 数组按下标访问 | 1 |
| O(log n) | 对数 | 二分查找 | 约 20 |
| O(n) | 线性 | 遍历数组 | 10⁶ |
| O(n log n) | 线性对数 | 归并排序、快速排序（平均） | 约 2 × 10⁷ |
| O(n²) | 平方 | 冒泡排序、双重循环 | 10¹² |
| O(2ⁿ) | 指数 | 穷举所有子集 | 无法完成 |

粗略估算：普通计算机每秒能做 10⁸ 量级的简单操作，n = 10⁶ 时 O(n²) 的算法要跑几个小时，而 O(n log n) 不到一秒。

分析技巧：单层循环 n 次是 O(n)；两层嵌套是 O(n²)；每次把问题规模减半是 O(log n)。还要区分**最好、平均、最坏**情况，比如快速排序平均 O(n log n)、最坏 O(n²)。

### 线性结构

| 操作 | 数组 | 链表 |
|------|------|------|
| 按下标访问 | O(1) | O(n) |
| 在头部插入 / 删除 | O(n) | O(1) |
| 在已知节点后插入 / 删除 | O(n) | O(1) |
| 内存布局 | 连续，缓存友好 | 分散，每个节点额外存指针 |

- **动态数组**：容量不够时申请 2 倍空间并复制，均摊下来每次追加仍是 O(1)。
- **栈**（后进先出，LIFO）：函数调用栈、括号匹配、撤销操作。
- **队列**（先进先出，FIFO）：任务排队、BFS。用数组实现时常做成**环形队列**，避免整体搬移。

### 哈希表

- 用**哈希函数**把键映射到数组下标，理想情况下查找、插入、删除都是平均 O(1)。
- 不同的键映射到同一下标叫**冲突**，常见处理方法：**拉链法**（每个桶挂一个链表）和**开放寻址法**（往后找空位）。
- **负载因子** = 元素数 / 桶数，过高时冲突变多，需要**扩容并重新哈希**。
- 前提是哈希函数分布均匀；最坏情况（全部冲突）会退化成 O(n)。

### 树与堆

- **二叉搜索树（BST）**：左子树所有值 < 根 < 右子树所有值。平衡时查找 O(log n)；按顺序插入已排序的数据会退化成链表，变为 O(n)，所以实际使用红黑树、AVL 树等**自平衡**树。
- **遍历**：前序（根左右）、中序（左根右，BST 的中序遍历得到有序序列）、后序（左右根）、层序（按层，用队列）。
- **堆**：完全二叉树，父节点总是不大于（小顶堆）子节点，可以用数组存储，下标 i 的子节点是 2i + 1 和 2i + 2。取最值 O(1)，插入和删除 O(log n)，用于优先队列和堆排序。

### 图

- 由**顶点**和**边**组成，边可以有方向、有权重。存储方式：**邻接矩阵**（n × n 数组，适合稠密图）或**邻接表**（每个顶点一个邻居链表，适合稀疏图）。
- **BFS**（广度优先）用队列，一层层向外扩展，可求无权图的最短路径。
- **DFS**（深度优先）用递归或栈，一条路走到底再回溯，可用于连通性判断、拓扑排序。
- 带权最短路径用 Dijkstra 算法（要求边权非负），入门阶段了解思想即可。

### 查找与排序

**二分查找**要求数组有序，每次和中间元素比较、排除一半，O(log n)。边界条件是最容易写错的地方：

```c
#include <stddef.h>
#include <stdio.h>

// 在升序数组 a[0..n-1] 中查找 key，找到返回下标，否则返回 -1
static ptrdiff_t binary_search(const int a[], size_t n, int key) {
    size_t lo = 0, hi = n;                    // 搜索区间 [lo, hi)
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;      // 避免 lo + hi 溢出
        if (a[mid] < key) {
            lo = mid + 1;
        } else if (a[mid] > key) {
            hi = mid;
        } else {
            return (ptrdiff_t)mid;
        }
    }
    return -1;
}

int main(void) {
    const int a[] = {2, 3, 5, 7, 11, 13, 17};
    size_t n = sizeof a / sizeof a[0];
    printf("%td %td\n", binary_search(a, n, 11), binary_search(a, n, 4));  // 4 -1
    return 0;
}
```

| 排序算法 | 平均时间 | 最坏时间 | 额外空间 | 稳定 |
|----------|----------|----------|----------|------|
| 冒泡 / 插入排序 | O(n²) | O(n²) | O(1) | 是 |
| 选择排序 | O(n²) | O(n²) | O(1) | 否 |
| 归并排序 | O(n log n) | O(n log n) | O(n) | 是 |
| 快速排序 | O(n log n) | O(n²) | O(log n) | 否 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 否 |

**稳定**指相等元素排序后保持原来的相对顺序。插入排序在数据基本有序时接近 O(n)，所以很多标准库在小数组上改用它。实际项目中用 C 标准库的 `qsort`，只需提供比较函数：

```c
#include <stdio.h>
#include <stdlib.h>

static int cmp_int(const void *pa, const void *pb) {
    int a = *(const int *)pa, b = *(const int *)pb;
    return (a > b) - (a < b);                 // 不用 a - b，避免溢出
}

int main(void) {
    int a[] = {42, -7, 19, 0, 3};
    size_t n = sizeof a / sizeof a[0];
    qsort(a, n, sizeof a[0], cmp_int);
    for (size_t i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    putchar('\n');                            // -7 0 3 19 42
    return 0;
}
```

> [!TIP]
> 写算法时先在纸上用一个小例子手动走一遍，特别是空数组、只有 1 个元素、目标在两端这几种边界情况。[VisuAlgo](https://visualgo.net/zh) 可以动画演示各种排序和数据结构的每一步。

## 常见误区

- **「O(1) 一定比 O(n) 快」**：大 O 忽略常数，n 很小时 O(n) 的简单遍历可能更快；它描述的是规模变大时的趋势。
- **「链表插入是 O(1)，所以总比数组快」**：前提是已经拿到了插入位置的节点，找到它本身要 O(n)；链表的缓存局部性也差。
- **「哈希表永远 O(1)」**：那是平均情况，前提是哈希函数好、负载因子合适。
- **二分查找写 `(lo + hi) / 2`**：下标很大时可能溢出，写成 `lo + (hi - lo) / 2`。
- **「刷题就是背答案」**：应先自己想、分析复杂度，做不出来再看题解，之后隔几天重做一遍。

先独立作答，再展开参考答案核对；简答题答出要点即算对。答对 ≥ 80% 即可进入下一关。

1. 【单选】在有 n 个元素的升序数组中二分查找，最坏时间复杂度是：
    - A. O(1)
    - B. O(log n)
    - C. O(n)
    - D. O(n log n)
2. 【单选】实现「撤销上一步操作」最合适的数据结构是：
    - A. 队列
    - B. 栈
    - C. 哈希表
    - D. 堆
3. 【单选】下面哪种排序算法最坏情况下仍是 O(n log n) 且稳定？
    - A. 快速排序
    - B. 堆排序
    - C. 归并排序
    - D. 选择排序
4. 【简答】哈希表为什么平均能做到 O(1) 查找？什么情况下会退化？
5. 【简答】按 1、2、3、4、5 的顺序插入一棵空的二叉搜索树，会得到什么形状？查找复杂度如何？怎样避免？

<details markdown><summary>参考答案</summary>

1. B — 每次比较排除一半，最多比较约 log₂n 次。
2. B — 撤销总是撤最近一次操作，符合后进先出。
3. C — 归并排序始终 O(n log n) 且稳定；堆排序不稳定，快速排序最坏 O(n²)。
4. 哈希函数直接算出键应在的桶，只需检查很少的元素。当哈希函数分布不均或负载因子过高、大量键冲突到同一个桶时，查找退化到 O(n)。
5. 每个节点只有右孩子，退化成一条链表，查找为 O(n)。使用红黑树、AVL 树等自平衡二叉搜索树可以保持 O(log n)。

</details>
