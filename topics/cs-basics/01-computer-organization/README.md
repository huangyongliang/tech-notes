## 知识要点

### 进制与十六进制

二进制太长，程序员习惯用十六进制（hex）书写：每 4 位二进制对应 1 位十六进制（`0`–`9`、`A`–`F`）。例如 `1111 1111` = `0xFF` = 255，`0x10` = 16。内存地址、颜色值（`#FF8800`）、文件内容的十六进制查看都用这种写法。

### 整数：无符号与补码

- **无符号整数**：n 位能表示 0 到 2ⁿ − 1。8 位是 0–255，32 位是 0–4294967295。
- **有符号整数用补码（two's complement）**：最高位权重是 −2ⁿ⁻¹。8 位能表示 −128 到 127。求一个数的相反数：按位取反再加 1。所以 −1 的 8 位补码是 `1111 1111`。
- 补码的好处：加法电路不区分正负，`5 + (−3)` 和 `5 + 253`（无符号）在 8 位里是同一串比特运算。
- **溢出**：无符号运算超出范围会按 2ⁿ 取模「回绕」，`255 + 1` 在 8 位里变成 0。C 语言中有符号整数溢出是**未定义行为**，不能依赖它回绕。

> [!NOTE]
> C23（ISO/IEC 9899:2024）开始，标准明确要求有符号整数用补码表示；此前标准还允许原码和反码，但主流硬件早就都是补码。

### 浮点数：IEEE 754

`float`（32 位）和 `double`（64 位）按 IEEE 754 存储：符号位 + 指数 + 尾数，相当于二进制的科学计数法。十进制的 0.1 在二进制里是无限循环小数，只能存近似值，所以 `0.1 + 0.2` 的结果并不严格等于 `0.3`。比较浮点数应判断差值是否足够小，金额计算应改用整数（以「分」为单位）。

下面的程序可以在本机验证这些结论（用 `gcc -std=c2x -Wall -Wextra numbers.c -o numbers` 编译）：

```c
#include <stdint.h>
#include <stdio.h>

int main(void) {
    uint8_t u = 255;
    u = u + 1;                          // 无符号回绕：255 + 1 -> 0
    printf("uint8_t 255 + 1 = %u\n", (unsigned)u);

    int8_t n = -1;
    printf("int8_t -1 的比特 = 0x%02X\n", (unsigned)(uint8_t)n);  // 0xFF

    double a = 0.1 + 0.2;
    printf("0.1 + 0.2 = %.17f, == 0.3 ? %s\n", a, a == 0.3 ? "是" : "否");

    uint32_t x = 0x01020304;
    unsigned char *p = (unsigned char *)&x;
    printf("0x01020304 在内存中的第一个字节 = 0x%02X（%s）\n",
           p[0], p[0] == 0x04 ? "小端" : "大端");
    return 0;
}
```

在 x86-64 机器上的输出：

```text
uint8_t 255 + 1 = 0
int8_t -1 的比特 = 0xFF
0.1 + 0.2 = 0.30000000000000004, == 0.3 ? 否
0x01020304 在内存中的第一个字节 = 0x04（小端）
```

### 字节序

多字节整数在内存中的排列顺序：**小端**（little-endian）把低位字节放在低地址，x86-64 和常见的 ARM 系统都是小端；**大端**（big-endian）反之，网络协议传输整数时约定用大端，所以叫「网络字节序」。

### CPU 怎样执行程序

```mermaid
flowchart LR
  F[取指 Fetch] --> D[译码 Decode] --> E[执行 Execute]
  E --> W[写回 Writeback] --> F
```

- 编译器把 C 代码翻译成机器指令，每条指令很简单：把数从内存读进寄存器、两个寄存器相加、比较、跳转。
- **寄存器**是 CPU 内部最快的存储，数量很少（x86-64 有 16 个通用整数寄存器）。
- **程序计数器（PC）**记住下一条指令的地址；跳转指令改变 PC，就实现了 `if` 和循环。
- **指令集架构（ISA）**是 CPU 和软件之间的约定，常见的有 x86-64、ARM64（AArch64）、RISC-V。同一个 C 程序要为不同 ISA 分别编译。
- 现代 CPU 用流水线、多发射、分支预测、乱序执行等手段同时处理多条指令，但对程序员呈现的效果仍然是「按顺序执行」。

在 [Compiler Explorer](https://godbolt.org/) 粘贴一个 C 函数，就能看到它对应的汇编指令。

### 存储层次与局部性

| 层次 | 典型容量 | 访问延迟数量级 |
|------|----------|----------------|
| 寄存器 | 几百字节 | 小于 1 纳秒 |
| L1 / L2 / L3 缓存 | KB 到几十 MB | 约 1–40 纳秒 |
| 内存 DRAM | GB 到几百 GB | 约 100 纳秒 |
| SSD | 几百 GB 到 TB | 几十到上百微秒 |
| 机械硬盘 | TB 级 | 几毫秒 |

表中数字只是数量级，因硬件差异很大，重点是**每往下一层慢 10 到 1000 倍**。缓存之所以有效，靠的是**局部性**：

- **时间局部性**：刚访问过的数据很可能马上再用（循环变量）。
- **空间局部性**：访问了某个地址，附近的地址很可能马上被访问（数组遍历）。缓存每次从内存搬一整块（缓存行，常见为 64 字节）。

C 的二维数组按行存储，所以按行遍历是连续访问，按列遍历每一步都跳一整行，缓存命中率低。CS:APP 第 6 章用实验展示了两者的速度差距。

## 常见误区

- **「有符号溢出会回绕」**：C 里那是未定义行为，编译器可能按「不会溢出」来优化，结果出人意料。只有无符号运算保证回绕。
- **「浮点数用 `==` 比较」**：几乎总是错的，应比较差值是否小于一个容差。
- **「内存访问都一样快」**：命中缓存和访问内存能差两个数量级，数据结构的内存布局直接影响速度。
- **「32 位、64 位只是软件版本」**：它指 CPU 寄存器和地址的宽度，决定了指针大小（64 位系统上通常是 8 字节）和可寻址空间。

先独立作答，再展开参考答案核对；简答题答出要点即算对。答对 ≥ 80% 即可进入下一关。

1. 【单选】8 位有符号补码能表示的范围是：
    - A. 0 到 255
    - B. −127 到 127
    - C. −128 到 127
    - D. −255 到 255
2. 【单选】`0x1F` 等于十进制的：
    - A. 15
    - B. 16
    - C. 31
    - D. 32
3. 【单选】访问下面哪一层存储最快？
    - A. L1 缓存
    - B. 内存 DRAM
    - C. SSD
    - D. 寄存器
4. 【简答】为什么按行遍历二维数组通常比按列遍历快？
5. 【简答】程序计数器（PC）的作用是什么？`if` 语句在机器层面是怎么实现的？

<details markdown><summary>参考答案</summary>

1. C — 最高位权重 −128，其余 7 位最多 127。
2. C — 1 × 16 + 15 = 31。
3. D — 寄存器在 CPU 内部，比 L1 缓存还快。
4. C 数组按行连续存储，按行遍历利用空间局部性，一次加载的缓存行里的数据都会被用到；按列遍历每次跳一整行，频繁缓存未命中。
5. PC 保存下一条要执行的指令地址。`if` 编译成「比较 + 条件跳转」指令，条件成立与否决定是否把 PC 改成另一处地址。
