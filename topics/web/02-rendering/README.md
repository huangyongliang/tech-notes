# 界面与渲染模型 {#ui-rendering}

> [Web](../) › 界面与渲染模型

前端框架约定的是：界面如何从状态推导出来，以及这次推导在什么时候发生。它不取消文档，也不取消源。

## 这一页补哪一块 {#rendering-scope}

[浏览器里的源](../origin/) 写方案、主机和端口，以及脚本默认可读的范围。本页不重讲三元组，也不教 HTML 标签或 CSS。框架名只用来说明「状态推导出界面」这一条约定，不是一份库的教程，更不是 Web 平台本身。

## 文档在下，推导在上 {#rendering-document}

浏览器先有文档和文档树。HTML 把文档当作树状的节点结构，页面上的元素是这棵树的一部分。浏览上下文负责展示其中一个文档。这是平台已经有的东西。

前端框架通常再约定一层：用当前状态算出应当显示的视图。它保证的是推导关系和更新边界：同样的状态应当得到同样的视图描述，状态变了才需要把文档改到和新描述一致。它不保证某一次虚拟 DOM 或 diff 算法的内部步骤。那些步骤是某个库把「描述」落到文档上的办法，换一个库可以换一套步骤，推导关系仍可以是同一条。

所以「用了前端框架」推不出「文档和源消失了」。框架产出的仍是要放进文档的结果。脚本能不能读另一个源的文档，仍由源决定。

## 数据没到，还是视图算错了 {#rendering-timing}

渲染时机要分开看。

1. 首次绘制：用当时已有的状态算出第一份视图。状态里可以还没有服务器的数据。
2. 状态变更之后：只重新推导受这次变更影响的那一部分，再把文档改到一致。
3. 和网络往返的关系：请求发出去，视图不会因此自动变成「数据已到」。返回之后，要有人把结果写进状态，推导才会变。

「数据还没到」是异步和边界问题。界面可以诚实地显示等待，这不表示推导算错了。「视图算错了」才是渲染约定没守住：状态里已经有购物车的三件商品，画面却仍按零件在画。请求是否已经到达，见 [计算机网络](../../cs-basics/05-networking/)。那一章的报文不等于本页的视图已经更新。

## 改路径不是换源 {#rendering-route}

客户端路由改的是地址栏里的路径，以及当前要显示的视图。整页导航会换掉文档，由服务器或下一次加载给出新文档。两条路都没有因为路径变了就换一个源。

源的比较不看路径。[浏览器里的源](../origin/) 已经写过：`/cart` 和 `/api/orders` 在方案、主机、端口相同时仍是同一个源。本页不重讲这个三元组。路由库把路径映射到哪个视图，是应用约定，不是浏览器对源的定义。

## 画得出来，不等于跨源可读 {#rendering-limits}

框架不保证这三件事。脚本默认可不可以读另一个源的响应，由源和 CORS 决定，不由组件画出来决定。Cookie 出现在请求里，也不自动变成「已经登录且安全」。后端资源是否正确，是请求处理和业务的事，不在「状态能算出一棵树」里。

跨源读取放在 [跨越源边界](../04-crossing-boundary/)。请求如何变成响应，放在 [请求处理与中间件](../03-request-handling/)。

同一份购物车状态，两种约定各管一段：

| 做法 | 这一侧约定了什么 | 留给网络的是什么 |
|------|------------------|------------------|
| 整页刷新，服务器生成 HTML | 服务器用当时的状态生成文档；浏览器展示这份文档 | 每一次查看都是一次新的文档请求。客户端不另持一份要推导的状态 |
| 客户端持有状态再推导 DOM | 状态变了就重新推导视图，再改文档 | 状态从哪一次响应写入，仍是请求的事。画得出来只说明本地推导跑过 |

第二种没有取消源，也没有把「请求已返回」写成「视图已经对」。

## 常见误读 {#rendering-misreadings}

- 「用了前端框架，就不存在文档和源了。」框架多了一层推导。文档仍是浏览器里的树，源仍按方案、主机和端口划分。
- 「路由变了就是换了一个网站（换源）。」路径不参加源的比较。换视图不等于换源。
- 「虚拟 DOM 或某库的 diff 等于渲染模型的定义。」diff 是某个库把新描述落到文档上的步骤。定义是「视图由状态推导」，不是那套步骤的名字。
- 「界面能画出来，就说明跨源 API 已经可读。」画面可以来自本地状态或同源文档。另一个源的响应正文默认可不可以交给脚本，是源的规则。

## 可选核对 {#rendering-check}

推导和源已经分开写了。这两问只核对哪一条没被框架取消。

1. 客户端路由从 `/cart` 变到 `/orders`，主机没变。源变了吗？
2. 购物车组件已经画出三件商品，但这些数字只写在组件的初始状态里，列表请求还没返回。这能说明跨源接口的正文已经交给脚本了吗？

<details markdown><summary>参考答案</summary>

1. 没有。源比较方案、主机和端口。路径变化只改要显示的视图，或触发一次导航。
2. 不能。画出来只说明本地状态被推导过。跨源正文是否可读，仍看源和 CORS，不看组件是否出现。

</details>
