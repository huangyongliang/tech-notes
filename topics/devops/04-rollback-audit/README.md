## 回滚的对象是先前那件制品 {#rollback-object}

回滚的对象是先前已经承认的制品，不是「把 Git 再 revert 一次，指望流水线长出差不多的东西」。能回滚的前提有三条，缺一条就不成立：旧制品还在，它的身份还在，来源证据还在。

身份是摘要。证据是绑在这个摘要上的来源陈述和当时的门禁结果。只有这些还在，才能把环境指回「上一份被承认的那一件」，而不是指回一个新编译出来的近亲。`git revert` 产生的是一次新的源修订。它可能触发一次新构建，那是另一条晋级，不是撤回旧的那一次。

## 什么时候这条保证还在 {#rollback-conditions}

回滚容易成立的条件：服务没有把自己的正确性绑在一套已经前移的数据格式上，协议对旧制品仍然向后兼容。典型情况是无状态服务，数据库还没有按新规则写入。此时把流量或期望状态指回旧摘要，请求仍按旧约定被处理。

保证被撤回的条件是下面任何一条已经发生：模式已经前进一步，数据已经按新规则写入，或其他进程可能已经处理过新版本发出的消息。镜像可以回到旧摘要，业务状态不一定回得去。旧制品看到新数据，会按它自己的约定失败，或者更糟，把新数据读成旧格式。

数据要怎样补偿，见 [分布式事务](../../microservices/07-distributed-transactions/) 里的 Saga 和 Outbox。那一章讲的是业务层的补偿，不是把镜像摘要换回去。超时也不等于没做：对方可能已经写入，只是响应没回来。[分布式系统模型](../../systems/distributed/) 说明这两种历史可以和同一次超时相容。所以「把镜像换回去」不能当成「分布式副作用已经撤销」。

短例子：生产已经跑过一次不可逆迁移，新列被写入之后，再把镜像回到旧摘要。旧程序不认识这套数据，请求失败。对照：只回滚无状态服务，数据库尚未切换。旧制品面对的仍是它验证过的那套数据，回滚保证还在。差别不在镜像还在不在，而在数据有没有越过旧约定。

## 自动回滚是写好的门禁反应 {#rollback-auto}

自动回滚是一种预先写好的门禁反应。例如错误率越过阈值，就把期望状态指回上一份制品。它依赖可观测信号。信号从哪来见 [可观测性](../../microservices/10-observability/)，阈值怎么配见 [微服务 14](../../microservices/14-cicd-gitops/) 的金丝雀条件。本页不讲采集栈。

没有可靠信号时，自动回滚会撤回「越改越安全」的直觉。错误的阈值可以把一次正常发布打回去，也可以在真正出错时不动。它是否更安全，取决于信号是否在量那件要撤回的事，以及旧制品是否仍满足上一节的条件。信号不可靠，自动化只是更快地执行一个未成立的撤回。

## 审计记录不是运行遥测 {#rollback-audit-log}

审计记录是流水线的产品之一。它要能复述：制品身份、来源证据、门禁结果、审批人、晋级和回滚的时间。事后核验靠这些陈述还在，而不是靠当事人回忆。SLSA 把验证定义为核对来源陈述；本页只取这一点，不把审计写成等级清单。

集群里的运行遥测是另一份记录。它回答「系统此刻表现如何」。流水线审计回答「我们当时承认了什么」。错误率升高可以触发自动回滚，但那条曲线本身不是放行记录。把监控日志当成审计，会在要问「谁放行了摘要 D1」时只找到「CPU 当时是多少」。

## 常见误读 {#rollback-misreadings}

- 「回滚就是 `git revert`。」revert 是一次新的源修订，往往引出一次新构建。回滚要指回仍然存在的旧制品及其证据。
- 「只要旧镜像还在，回滚就一定安全。」镜像可以回到旧摘要。数据或已发出的消息若已经按新规则往前走，旧制品的约定就不再成立。
- 「集群或监控里的日志，就是流水线的审计。」遥测回答系统表现如何。审计要回答当时承认了哪一份制品、谁放的行。
- 「自动回滚一定比不回滚更安全。」它只是按阈值执行撤回。信号不可靠，或旧制品已经配不上新数据，自动化不会把保证补回来。

## 可选核对 {#rollback-check}

条件和记录已经分开写了。这两问只核对保证还在不在。

1. 旧镜像的摘要还在仓库里，生产的数据迁移已经写完。把流量指回旧摘要，回滚保证还成立吗？
2. 监控里能看到错误率曲线和容器日志。这是否就是「谁在何时放行了哪一个摘要」的审计？

<details markdown><summary>参考答案</summary>

1. 不成立。旧制品还在，只满足身份那一条。数据已经按新规则写入，旧约定被撤回。镜像回到旧摘要，请求仍可能按新数据失败。
2. 不是。曲线和容器日志是运行遥测。审计要有制品身份、来源证据、门禁结果、审批人和时间。两份记录回答的不是同一个问题。
