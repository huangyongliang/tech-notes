# 规格与实现 {#specification-implementation}

> [软件工程理论](../) › 规格与实现

规格写的是必须成立的性质，以及实现仍可以自由做什么。实现是其中一种满足方式。规格没说的地方，实现不受它约束。

## 这一页补哪一块 {#spec-scope}

第 02 章划的是变化落在哪个模块。本页划的是：哪些性质被写成可检查的约定。不写需求文档模板，不画用例图，也不教形式化工具。[编程](../../programming/) 写语言定义约束程序的含义。[产品调研](../../product-research/) 写为什么选这个。两者都要可核对，核对的对象不同。

## 约束的是性质，不是某一段代码 {#spec-observable}

规格约束可观察的行为或性质。实现可以换，只要仍落在约定里。一段设计文档若只描述某次选定的代码结构，它还不是这种约定。代码本身是一种实现。把代码叫作规格，就没有了「还可以有另一种满足方式」这一层，也没有独立于这版代码的检查标准。

这和语言定义不是一件事。[编程](../../programming/) 里，实现必须遵守语言定义，但某次编译结果不是定义本身。语言定义约束的是程序的含义。规格约束的是这份软件要满足的性质。遵守了语言，不自动满足规格。满足规格的两种实现，仍必须各自是合法程序。

规格长，也不等于完整。篇幅可以都花在一种实现的步骤上，该说的性质仍然没说。

## 三种缺口 {#spec-gaps}

有缺口的规格不能单独承担「已经做对了」的证明。

| 缺口 | 含义 | 检查会怎样 |
|------|------|------------|
| 不完整 | 该说的性质没说 | 实现可以在沉默处各行其是，规格都算满足 |
| 不一致 | 条款互相冲突 | 没有任何实现能同时满足，或满足一方必违反另一方 |
| 不可检查 | 没有办法判断是否满足 | 通过或失败都无法对照这条约定 |

写了很长的设计说明，若对不上可观察的性质，仍然可能三种缺口都在。前置条件和后置条件是陈述责任的一种方式，不是把这三种缺口自动补上。

## 责任如何被陈述 {#spec-contract}

Meyer 用约定划分责任：调用方保证前置条件，实现方在该前提下保证后置条件，不变式在对象可被观察时成立。本页只取这个划分，用来说明「谁保证什么」。不写成某一语言的契约库教程，也不写成形式化证明。写了前置和后置，只是把责任说成了可检查的句子。证明这些句子在所有允许的执行里成立，是另一件事，见第 04 章。若要形式系统，逻辑的定义在 [理论基础](../../cs-theory/01-logic/)，本页不复述证明系统。

与产品调研的分界也在核对对象。[产品调研](../../product-research/) 的选型记录留下「为什么选这个」：问题、判据、事实和未选项。规格留下「选了之后，行为必须满足什么」。一份选型不能代替规格，一份规格也不说明当时为什么在备选中选了它。

## 规格沉默的地方 {#spec-example}

规格写两条：余额不足则拒绝，并且账户总额不变。这是性质，不是某一段代码。

一种实现先扣再查，失败时把扣掉的加回去。另一种先查再扣。在没有并发的假设下，两者都可能让单次调用满足这两条：不足的被拒绝，成功的一次扣减使总额仍与规则一致。

一旦允许并发，规格若没写清两次操作能否干涉，它就没有约束交错发生时的总额。两种实现都可以在交错下让总额偏离，而单次看起来仍符合那两句。规格沉默之处，实现不受约束。并发下何种交错合法，见 [Java 05](../../java/05-concurrency/) 或 [分布式系统模型](../../systems/distributed/)。本页不重写那些模型，也不把这个例子做成一套账户业务。

## 常见误读 {#spec-misreadings}

- 「有详细设计文档，就等于有规格。」文档若只描述一种结构，而没有可观察的性质，它还是实现说明。
- 「代码即规格，所以不必再写约定。」代码是一种实现。没有独立约定，就无法说另一种实现是否仍算满足。
- 「规格越长越完整。」长度可以堆在步骤上。该说的性质没说，就是不完整。
- 「写了前置和后置条件，就等于做了形式化证明。」那只是责任被陈述成了可检查的句子。证明它们成立是另一件事。

## 可选核对 {#spec-check}

缺口和沉默已经分开。这两问只核对约定约束到了哪里。

1. 两份实现都通过了语言的类型检查，行为不同。能否说它们都满足规格？
2. 规格没写并发下的总额。一种实现在交错时总额变了。它违反了这规格吗？

<details markdown><summary>参考答案</summary>

1. 还不能。类型检查是语言定义里的一类约束。规格约束的是这份软件的性质。两件合法程序仍可能一个满足规格、一个不满足，或规格本身没说。
2. 就这规格而言，不能说它违反。规格没有写干涉。沉默之处实现不受约束。要约束交错，得把那条性质写进规格。

</details>
