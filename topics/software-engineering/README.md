# 软件工程理论 {#software-engineering}

本主题讨论软件工程约束什么：变化落在哪里，哪些性质被写成可检查的约定，以及一种检查究竟证明了什么。它不建过程框架、设计模式或 UML 目录。

## 工程是一组约束 {#se-constraint}

软件工程面对的是会变化、而且无法一次完全写清的系统。它不取消问题本身的复杂性。它规定三件事：哪些变化被限制在局部，哪些性质被写成可检查的约定，以及一种检查手段的效力停在哪里。

本质复杂性不会因为换语言、换过程或换工具而消失。那些手段最多去掉偶然复杂性，也就是表示和工具带来的额外负担。这个分界在 [复杂性与变化](01-complexity-change/) 展开。后面三章分别写模块如何划定变化、规格如何写成可检查的约定、验证能证明什么。

[理论基础](../cs-theory/) 是形式化的计算科学，不是软件工程。本主题不把可计算性写成「工程难」的同义词。[编程](../programming/) 写语法、语义、类型和求值，并且已经声明不建设计模式目录。本主题讨论模块与规格，不回头写语言定义，也不补模式百科。[编程入门](../programming-basics/) 写如何用 C 写出程序。本主题不教语言或工具。[Java 08 测试](../java/08-testing/) 和 [微服务 15 测试](../microservices/15-testing/) 写具体栈上的测试。第 04 章只问一种检查能证明什么。[DevOps](../devops/) 写流水线保证什么。门禁是检查的一种落地，不是验证理论。[产品调研](../product-research/) 写判断如何挂在事实上。规格是关于行为的约定，不是选型备忘。

读过编程入门、再对照编程主题，会最顺。这不是 Java、微服务或理论基础 12–14 的先修，也不插入学习路线成为必经关卡。
