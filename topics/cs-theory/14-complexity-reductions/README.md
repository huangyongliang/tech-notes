## 从「容易检查」和「容易找到」开始

给一组互不冲突的测试模块，逐对检查很容易；要求在任意冲突图中找到至少 k 个互不冲突的模块，就可能需要复杂搜索。这里的落差不是「不会写代码」，而是需要精确定义输入规模、答案类型和可验证证书。

## 知识要点

### 先固定判定问题与输入编码

P、NP 通常讨论答案为是或否的语言。优化问题「最大独立集有多大」对应判定版本「是否存在大小至少为 k 的独立集」；不要直接把两类定义混写。

输入规模 N 是**编码位数**，不是某个数的数值。例如二进制正整数 W 的长度为 `⌊log₂ W⌋+1`；一个 O(W) 时间算法可能对 W 的位长度是指数级，因此只按 W 多项式运行常被称为伪多项式，不能据此直接归入 P。

已有 [DSA](../../cs-basics/06-data-structures-algorithms/) 讲大 O 和具体操作计数；本关不重讲排序表，而讨论「是否存在某类算法」及问题间转换。多项式时间也不等于实际一定快，巨大次数和常数仍可能不可用。

### P、NP 与证书

- **P**：存在确定算法，对每个输入都在输入长度的多项式时间内正确判定。
- **NP**：肯定实例有一个长度不超过输入长度某个多项式的证书，且存在确定的多项式时间验证器；否定实例不能有会被该验证器误接受的证书。

NP 也等价于非确定图灵机多项式时间可判定的语言类，但它不是「Non-Polynomial」的缩写。P 包含于 NP，因为能直接快速判定，就可以忽略证书。NP 的定义并不要求「否」答案也有同样类型的短证书。

例如大小至少 k 的独立集，证书可列出 k 个不同顶点；检查范围、去重及每对之间没有边即可，证书长度和验证时间都是图编码长度的多项式。证书不是「我相信能找到」的一句话。

### 多项式归约与 NP 完全

多项式时间多对一归约 `A≤ₚB` 要求存在确定多项式时间映射 f，对每个实例 x 有 `x∈A ↔ f(x)∈B`。若 B 在 P 中，则 A 也在 P 中；复合的多项式仍是多项式。

- B 是 **NP-hard（NP 难）**：NP 中每个问题都能多项式归约到 B。
- B 是 **NP-complete（NP 完全）**：B 同时 NP-hard 且属于 NP。

要证明新的 B 是 NP 完全，通常先证明 B 属于 NP，再从一个已知 NP 完全的 A 归约到 B，最后证明变换多项式且是/否答案双向等价。只做 `B≤ₚA`，说明 B 可以借 A 求解，不足以证明 B 已经同样难。

引用 Cook–Levin 定理：SAT（命题公式是否存在满足赋值）是 NP 完全的；3-SAT、一般图的独立集、顶点覆盖、哈密顿圈判定也是标准 NP 完全问题。本关不提供这些既知起点的全部困难性证明；后面的归约演示从已知独立集开始。

### 未解决不等于已经证明很慢

截至核对日期 2026-11-06，P 是否等于 NP 仍是开放问题。如果任意一个 NP 完全问题在 P 中，则 P=NP；若证明其中一个不在 P，就得到 P≠NP。

NP 完全不是不可判定：标准有限编码下，NP 问题可用有限穷举判定，只是穷举可能极慢。也没有已知结论说所有 NP 完全问题的每一种实例都难，或已证明每种精确算法都必须指数时间。

## 小例题

### 例一：独立集与顶点覆盖互补

独立集 S 中任意两点没有边；顶点覆盖 C 要让每条边至少有一个端点落在 C。对同一简单图 G，有 `S 是独立集 ↔ V\S 是顶点覆盖`：

- 若 S 内没有边，任何边至少有一端不在 S，故补集覆盖全部边。
- 若补集覆盖全部边，就不存在两端都在 S 的边，故 S 独立。

因此把独立集实例 `(G,k)`，其中 `0≤k≤n`，变成顶点覆盖实例 `(G,n−k)`，便有「至少 k 个独立点」当且仅当「至多 n−k 个覆盖点」。无需取图的补图，保持 G 不变；只换参数即可，多项式时间完成。这演示正确的困难性传递方向，不是从两道题外表相似就断言等价。

### 例二：一个具体证书

冲突图 `V={a,b,c,d,e,f}`，边为 `ab, bc, cd, de, ef, fa, ad`。取 `S={a,c,e}`，其中三对点都没有边，所以是大小 3 的独立集。其补集 `{b,d,f}` 覆盖全部 7 条边，可逐条核验。

这是一个实例的肯定证书，不证明所有同规模图都有 3 点独立集，也不证明搜索算法对所有图都快速。对于二分图的最大匹配、DAG 的拓扑排序、非负权最短路，前面已经给出多项式算法；「图问题」不是一个统一的难度标签。

## 和 Java、微服务、AI 的衔接

业务的分配、排程、依赖优化可能包含困难的组合核心。实际可以限制输入结构、使用近似、启发式、分支定界、求解器并设置预算；但应该说明返回的是可行解、最优解还是尚未证明的候选。AI 很快给出一个方案，不等于证明全局最优，也不会自动改变该一般问题的最坏情况分类。

NP 难问题也可能在树、二分图或小参数条件下变容易；模型发生变化要重新论证，不能把一般图分类盲目移植过去。

## 通关自测

1. 一个问题已有确定 O(N³) 判定算法，属于 P 吗？也属于 NP 吗？能断言所有输入都实际处理得很快吗？
2. 已知 A 为 NP 完全，且 `A≤ₚB`。还需要证明 B 的什么性质，才能称 B 为 NP 完全？
3. 在例二中独立集参数 k=3，对应顶点覆盖参数是多少？把 k 改为 4，如何只借一个顶点覆盖判定器来问原问题？
4. 算法对二进制输入整数 W 执行 W 次循环，每次工作为常数；为什么不能直接说「线性，所以属于 P」？

<details markdown><summary>参考答案</summary>

1. 按 N 是输入编码长度的前提，它在 P，也在 NP。多项式分类不承诺具体常数、输入规模和工程耗时。
2. 已得 NP-hard，还要证明 B 属于 NP，即有多项式长度证书和多项式时间验证器；若 B 的编码或范围不标准，也要先定义清楚。
3. 参数为 3；k 为 4 时，问同一图是否有至多 `6−4=2` 个点的顶点覆盖，其答案等价于是否存在至少 4 个点的独立集。
4. 长度 N 的二进制整数可达接近 `2^N` 的数量级；W 次循环对 N 可能指数增长。数值线性不等于编码长度多项式。
