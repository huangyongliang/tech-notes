## 从一道规则谜题开始

一个构建器只有两条规则：「如果启用了签名，就必须提供证书」「缓存命中或离线包可用时可以继续」。给出一次运行记录，怎样判定它违反了哪条规则？先不要写代码，先区分三个东西：**事实的真假、规则的真假、执行某个动作的决定**。

设 `P` 表示启用签名，`Q` 表示提供证书。规则是 `P → Q`，读作「若 P 则 Q」。它只排除「启用签名但没有证书」；没有启用签名时，这条规则没有要求一定提供或一定不提供证书。

## 知识要点

### 命题、连接词与等价

命题是在给定语境下具有真或假值的陈述。「目录里恰有 4 个文件」固定目录和时刻后是命题；「请打开目录」不是。这里采用经典二值逻辑：一句已经解释好的命题要么真，要么假。

这不是 SQL 的比较。PostgreSQL 18 的文档写明，普通比较在任一输入为 NULL 时得到 null，并称之为 unknown，不是 true 或 false；`7 = NULL` 的结果是 null，判断空值要写 `IS NULL`。SQLite 的 NULL 说明也指出，这种结果不能按经典二值从字面推出来，例如 `NULL OR true` 在常见引擎里为 true，而未知比较不会因为「不是假」就变成真。数据库章讲 SQL。本页不把 NULL 的三值表当成另一种要在这里学完的逻辑。

| 写法 | 读法 | 为真的条件 |
|------|------|------------|
| `¬P` | 非 P | P 为假 |
| `P ∧ Q` | P 且 Q | 两者都真 |
| `P ∨ Q` | P 或 Q | 至少一个真，允许都真 |
| `P → Q` | P 蕴含 Q | 不是「P 真且 Q 假」 |
| `P ↔ Q` | P 当且仅当 Q | 两者真值相同 |

`P → Q` 等价于 `¬P ∨ Q`，也等价于逆否命题 `¬Q → ¬P`，但通常不等价于逆命题 `Q → P`。在前面的规则中，「有证书」是「启用签名」的必要条件，不是充分条件。

日常的「如果…就…」常常暗示原因或预期。这里的蕴含不表示原因。经典逻辑只有真、假两种真值。下面四行是蕴含式在四种赋值下的输出，不是四种真值：按 (P, Q) 的顺序 (真, 真)、(真, 假)、(假, 真)、(假, 假)，`P → Q` 的结果依次为真、假、真、真。它为假的唯一一行是前件真而后件假；前件为假的两行，结果都为真，只表示这条规则没有被违反。所以「签名关闭，证书未提供」不违反 `P → Q`。中文「只有 Q，才 P」读成 `P → Q`，Q 是 P 的必要条件，不是 `Q → P`。因此「只有通过校验，才允许安装」写成「允许安装蕴含通过校验」；通过校验仍推不出允许安装。通关自测第 1 题是在用这个读法。这四行只核对两个命题变元，不是对更多变元的证明。

德摩根律是 `¬(P ∧ Q) ↔ (¬P ∨ ¬Q)` 和 `¬(P ∨ Q) ↔ (¬P ∧ ¬Q)`。**逻辑等价**要求对所有真值赋值都相同，不是恰好在某次运行里相同。恒真式对所有赋值为真；可满足式只要求至少一个赋值为真。

### 谓词、论域与量词

`Ready(x)` 的真假依赖对象 x，叫谓词。先分写法、指派和句子。`P → Q` 与 `Ready(x)` 首先都是公式，这一层只谈符号怎么组。`Ready(x)` 的 x 没有被量词绑住，也没有被常元替换，它仍是带自由变元的开公式，不是句子。只规定论域、并规定 Ready 表示「该模块就绪」，这是解释，并不把 x 绑住，开公式因此还不是句子。在这个解释下，若再把 x 指派成某一个模块，才能说这个开公式在该指派下为真或为假；那是指派下的真值，公式本身仍开着。要得到句子，须用量词绑住 x，例如 `∀x Ready(x)`，或把 x 换成一个不带变元的名字。换论域或改 Ready 的含义，会换成另一个解释。下面先采用「本次构建的全部模块」这个解释，下列各句里的量词已经绑住变元，所以它们是句子：

- `∀x Ready(x)`：每个模块都就绪。
- `∃x Ready(x)`：至少一个模块就绪。
- `∀x ∃y Depends(x,y)`：每个模块都有某个依赖，依赖可随模块而不同。
- `∃y ∀x Depends(x,y)`：存在一个共同依赖，所有模块都依赖它。

后两句不能交换量词。若模块只有 A、B，且仅 A 依赖 B、B 依赖 A，则第一句成立，却没有一个模块被所有模块依赖。

否定量词时要翻转量词并否定内部谓词：`¬∀x P(x)` 等价于 `∃x ¬P(x)`；`¬∃x P(x)` 等价于 `∀x ¬P(x)`。两层量词就把同一规则用两次。`¬∀x ∃y Depends(x,y)` 先写成 `∃x ¬∃y Depends(x,y)`，再写成 `∃x ∀y ¬Depends(x,y)`：有一个模块，它对论域里每个对象都不满足 Depends。这和 `∀x ∃y ¬Depends(x,y)` 不同，后者允许每个模块各自不依赖一个不同的对象。论域必须写明：镜像集上的全称和平台集上的存在不是同一个变元的两种写法。通关自测第 2 题只是把这两步用到另一句句子上。空论域上，全称为真，存在为假；这不是断言有一个「空对象」。在只有 A、B 的有限论域上逐对检查，只能核对这个论域。

## 小例题

### 例一：找出一条违例记录

记录是「签名关闭，证书未提供」。这不违反 `P → Q`，因为 P 为假。记录「签名开启，证书未提供」才是反例。若产品真实需求是「仅在签名开启时才提供证书，并且开启时一定提供」，就应写 `P ↔ Q`；这比单向规则更强。

下面用完整 C 程序穷举两变量的真值；表达式都没有副作用。保存为 `logic.c`，用 `gcc -std=c17 -Wall -Wextra -Werror logic.c -o logic` 编译。

```c
#include <assert.h>
#include <stdio.h>

int main(void) {
    for (int p = 0; p <= 1; ++p) {
        for (int q = 0; q <= 1; ++q) {
            int implication = !p || q;
            int contrapositive = q || !p;
            assert(implication == contrapositive);
            assert(!(p && q) == (!p || !q));
            printf("%d %d %d\n", p, q, implication);
        }
    }
    return 0;
}
```

输出的三列为 P、Q、蕴含式：依次是 `0 0 1`、`0 1 1`、`1 0 0`、`1 1 1`。C 的 `&&`、`||` 有短路求值，含自增、函数调用等副作用时，不能仅凭真值等价就重排求值；语法见 [C 核心概念](../../programming-basics/02-core-concepts/)。

同一点的 Java 对照：

```java
class Implication {
    public static void main(String[] args) {
        for (int p = 0; p <= 1; ++p) {
            for (int q = 0; q <= 1; ++q) {
                boolean pb = p != 0;
                boolean qb = q != 0;
                boolean implication = !pb || qb;
                boolean contrapositive = qb || !pb;
                if (implication != contrapositive) {
                    throw new AssertionError();
                }
                if ((!(pb && qb)) != (!pb || !qb)) {
                    throw new AssertionError();
                }
                System.out.printf("%d %d %d%n", p, q, implication ? 1 : 0);
            }
        }
    }
}
```

### 例二：否定一个带条件的保证

「每个已发布包都有校验文件」写为 `∀x (Published(x) → HasChecksum(x))`。否定它得到 `∃x (Published(x) ∧ ¬HasChecksum(x))`：找出一个已发布却缺校验文件的包即可，不能只找一个未发布包。

1. 把「只有通过校验，才允许安装」写成蕴含式；校验通过是否已保证允许安装？
2. 否定「存在一个镜像，能构建所有目标平台」，说明每层量词的论域。
3. 设 P 为真、Q 为假，分别计算 `P → Q`、`Q → P`、`P ↔ Q`。
4. 模块集合为空时，「所有模块均已扫描」与「存在已扫描模块」分别是什么真值？这能证明扫描器实际运行过吗？

<details markdown><summary>参考答案</summary>

1. 设 A 为允许安装，C 为通过校验，写 `A → C`。不能推出 `C → A`，仍可能因为版本不兼容而禁止安装。
2. 原式为 `∃m ∈ 镜像集，∀p ∈ 平台集，Builds(m,p)`；否定是 `∀m ∈ 镜像集，∃p ∈ 平台集，¬Builds(m,p)`。失败的平台可以随镜像改变。
3. 依次为假、真、假。蕴含式仅在前件真且后件假时为假。
4. 依次为真、假。空集合没有违例，也没有见证，逻辑结论不能证明运行事件实际发生。
